# CatChess V4 Pro：编译式几何融合与多搜索汇总

本页描述冻结候选的实现。最终模式为三个自有搜索工作进程；是否满足正式验收，以 `v4-pro-release-summary.json` 为准。开发筛选与失败候选单独保留。

## 网络知识来源

保留本项目 V3.2 的 863,522 个神经参数和 160 维几何输入。没有引入 Pikafish 的搜索代码、NNUE 参数或运行时调用。本次发布路线没有重新训练参数；尝试过的 64/64 残差价值头在开发对局中未领先，因此未被选入发行模型。

逻辑网络保持：共享绝对位置 64＋己将九宫残差 64（逐元素相加），轴向关系 32；双方视角各 96，拼接后 192；绝对位置与关系的乘积 32；几何 160；共 384 输入，经过 64 单元 ReLU 与连续阶段输出，修正子力先验。

## 编译式条件嵌入

原模型每子每视角贡献六个令牌：共享位置、将位残差、相对双方将帅的横纵四个轴向令牌。V4 启动时将这些固定参数重排为派生缓存：

1. 对每个己将九宫格和棋子令牌，将共享位置与该将位残差相加，得到一行 64 维条件位置向量。
2. 对每个将帅阵营、九宫格和棋子令牌，预先合并横纵位移，得到一行 32 维关系向量。
3. 移子时读取三行：一行条件位置、两行将帅关系。以 int32 相加，精确保留原令牌和。

所有合并行先检查 int16 范围。派生缓存占 2,903,040 字节，不计作新增可训练参数；它增加约 2.77 MiB 常驻数据，以换取更少查表与循环。异常诊断 FEN 保留原令牌计算回退路径。将帅移动仍重建条件状态。

原累加器为双方各分配 160 项几何原始矩，但只有前 96 项需要增量保存。V4 将状态压到 96；其余 64 项攻击与通路结构从当前棋盘生成。这减少延迟累加器栈的复制量，没有减少几何输入维数。

## 稀疏整数融合

融合层仍使用输入尺度 1024、系数尺度 8192 的整数点积。V4 将权重从“每个输出神经元一行”转成“每对输入覆盖全部输出”的布局：

- 将两个 int16 输入合成一个 32 位广播值。
- 每个 AVX2 向量同时计算八个输出的成对乘积和。
- 输入对均为零时跳过整块。此时乘积严格为零，未作近似裁剪。
- 保留逐行最坏 int32 溢出界检查。

重新排布不改变整数点积结果；与独立逐行标量参考进行整批局面验证。该优化改变推理架构与数据流，不增加隐藏层或参数。

## 几何结构的预计算拓扑

保留三空间的全局、己方、敌方矩，共 96 维。另有车炮射线、炮架、马腿、象眼、受攻、保护与将区结构，共 64 维。

V4 为每个棋盘格预先生成射线及非直线棋子的目标格与阻挡格。评分时直接读取这些拓扑，按当前占据关系处理阻挡。攻击计数采用整数统计，最后一次性归一化。所有 64 个输出与 V3 的规则结构实现逐项精确一致。

这些结构仍是未过滤全部牵制的神经输入，不是完整合法着法表，也不会直接添加一套手写评价分。

## 搜索改变

- 延迟构造着法排序分数：先完成合法着法与早期剪枝检查，幸存节点才访问历史表并排序。
- 在静态搜索中，已缓存的有效边界可在生成全部候选前返回；保留重复局面优先条件。
- 使用与静态估值方向相容的置换表边界辅助浅层剪枝。
- 为吃子维护带衰减的历史排序信息；新局清空。
- 选择性捕获验证：在非主变化的足够深节点，以提高的分数门槛先做静态搜索，再做减深验证；成功只作为边界返回，不当作精确评分。
- 将探测到的置换表条目复制到当前栈帧，避免递归搜索替换同一槽后再读取失效内容。
- 将军检测使用反向马腿和射线拓扑；将帅位于本方九宫时，对方士象不可能合法攻击到该宫，省去每次重复扫描。合法性探测复用已经找到的将帅格，避免再次寻找。

每个工作进程保留原有 PVS、子力门控空着、SEE、奇异着法验证、延迟累加器、根节点减深与完整重搜、PV 安静将军和独立杀棋证明；每个工作进程单线程、64 MiB 置换表。

## 三个自有搜索工作进程

默认启动一个协调进程和三个搜索工作进程。工作进程运行同一个 V4 可执行文件的内部 `--worker` 模式；不是外接其他引擎，也不需要额外模型文件。三个工作进程读取同一套已训练参数，逻辑神经参数仍是 863,522，不按副本重复计数。

三个搜索采用不同的对数减深系数（2.4、2.0、2.8），分别偏向原策略、更积极减深、较保守减深。它们各有独立置换表和历史信息，并行处理相同局面。协调进程按候选一致性、已完成深度和评分生成投票权重，优先汇总各搜索都支持的着法；具有杀棋分的结果单独处理。

这是一种多搜索汇总，不是共享置换表的 Lazy SMP。它用额外 CPU 与内存取得同一等待时间下的更强结果，不能当作相同 CPU 工作量的架构消融。每个工作进程获得相同墙钟预算，协调进程等待并汇总；比赛保留每手外部墙钟耗时。`go nodes N` 的预算分摊给三个工作进程，而不是各自再给 N。

`CatChess-V4-pro.exe --worker 0` 可直接运行单搜索核心；多核验收成绩不适用于该模式。全部模式的几何和价值网络相同。

## 发布判断

冻结最终候选和基线哈希后，生成新开局种子；以 V3.2 为主基线，双方等时、每个开局交换红黑。V4 为三个搜索工作进程，V3.2 为一个；最终主要 64 局为 100 毫秒，复验 32 局为 300 毫秒。预先要求每批得分率至少 60%，合并规范化开局簇 bootstrap 95% 下界超过 50%，所有棋谱独立回放通过。

开发期间还筛选过残差网络、额外捕获减深和双奇异延伸。单搜索 R1 在 200 毫秒 64 局中取得 22 胜、32 和、10 负，59.375% 得分，未达预设门槛；其后续 600 毫秒复验完成 12 局后停止。单搜索 R2 增加将军检测后为 18 胜、37 和、9 负，57.031%，同样未达门槛，其后续复验未完成。

最终 R3 转为多搜索汇总，经用户明确选择以多核为 Pro 默认模式，重新冻结后更换开局种子与测试时限。前两次失败不并入 R3 成绩，未完成的复验明确标注不完整。

完整开发记录保留，不并入最终候选的验收统计。比赛使用三次重复或 240 半回合判和、无合法着法判负，不以估值提前裁决。没有完整长将长捉裁判、开局库或残局库。
