## 开发历史与失败尝试

64/64 残差网络重新训练 32 轮，验证和残局误差略有改善，但 24 局开发对战仅 5 胜、13 和、6 负，47.9% 得分，未发布。捕获减深与双奇异延伸候选也未采用。

首个冻结候选 R1 在 200 ms 的新 64 局为 22 胜、32 和、10 负，59.375%，未达预设 60% 门槛。其 600 ms 后续对局在完成 12 局后因首批已不合格而停止；保留 JSON 并明确标为不完整，不与正式成绩合并。单工作进程 R2 增加精确将军检测后，新的 64 局为 18 胜、37 和、9 负，57.031%，仍未达标；后续复验未完成。

最终 R3 转为三个独立搜索工作进程，用户明确选择多核、棋力优先。重新冻结后采用新的 100 ms / 300 ms 两批种子；每批仍要求至少 60%，合并规范化开局簇置信区间下界仍要求超过 50%。先前 200 / 600 ms 数据不并入最终成绩，也不能用新成绩声称已通过这两个未完成的时限。

开发筛选对局不计入本页最终成绩。既有 V3.2 / V3 Pro 程序未修改、未降配。

## 实用边界

这是在用户选择多核模式后的相同墙钟时间比较：V4 三个搜索工作进程，V3.2 一个，CPU 与内存成本增加。单工作进程优化虽有优势方向，但两次正式筛选未达到门槛，不能将多核成绩说成相同 CPU 预算下的纯模型优势。

仍采用项目现有简化重复规则，没有完整长将长捉、开局库与残局库。测得优势不能推断所有开局与设备均领先，也不能从参数量或内部搜索节点推算大语言模型的等效参数量。

本次没有新增模型训练；863,522 参数来自自有 V3.2，三空间坐标与父模型包含历史知识。运行时不调用 Pikafish；本次正式验收也没有以皮卡鱼为对手。
